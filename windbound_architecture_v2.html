📋 Executive Summary

Windbound is a containerized input management system that serves as a critical component in the Windrunner pipeline. It orchestrates the collection, preparation, and distribution of input artifacts required for downstream container execution. The system integrates with multiple external services including Windstorm API for workflow orchestration, MinIO for object storage, and Git repositories for template management.

Key Purpose: Windbound acts as the input builder and dependency resolver in a multi-stage containerized workflow, ensuring that each execution has the correct artifacts and dependencies available before processing begins.

Functional Decomposition

Authentication Layer

  • login_minio() - Creates S3-compatible MinIO client with credentials
  • login_windstorm_api() - Obtains OAuth2 bearer token from Keycloak
  • Uses client credentials grant flow for service-to-service auth

Workflow Orchestration Layer

  • update_thread_status() - Reports execution progress to Windstorm
  • check_thread_dependency() - Resolves action dependencies
  • Supports windrunner_1 (started) and windrunner_2 (completed) states

Artifact Management Layer

  • download_dependent_output() - Fetches outputs from previous threads
  • create_bucket() - Packages and uploads input artifacts to MinIO
  • Manages retention policies and versioning

Template Processing Layer

  • clone() - Clones template repository from Git host
  • template_render() - Processes Jinja2 templates with context data
  • Supports parameterized artifact generation

Volume Management Layer

  • init() - Initializes Git repository in attached volume
  • Prepares shared filesystem for downstream containers
  • Validates volume mount at /mnt/vol

🚀 Deployment Design

Kubernetes Deployment Architecture

Container Lifecycle

1. Initialization Phase

  • Container starts from python:3.11-slim base image
  • Git system package installed via apt-get
  • Python dependencies installed from requirements.txt
  • Working directory set to /app
  • Source code copied from src/ directory

2. Pre-Execution Checks

  • Creates /app/tmp directory for temporary files
  • Validates volume mount at configured VOLUME path
  • Raises NotImplementedError if volume not attached
  • Loads environment variables via env.py

3. Execution Phase

  • Invokes main() function via Fire CLI framework
  • Accepts command-line arguments: action, thread_execution_id, prev_thread_name
  • Executes 10-step workflow sequence
  • Updates Windstorm API with progress status

4. Completion Phase

  • Prints execution time statistics
  • Updates final status to windrunner_2
  • Leaves artifacts in shared volume for next container
  • Container exits with status code 0 on success
